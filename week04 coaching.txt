[Coach]: This is a solid, clean implementation of a controller function, Sampson. Looking at your code, what is the specific reason or advantage of passing category_name back to the res.render call inside your validation error block (if (!errors.isEmpty()))?

// 1. Defined in src/utilities/category-validation.js
import { body } from 'express-validator';

export const categoryRules = () => {
    return [
        // Validates the 'category_name' input field from the form
        body('category_name')
            .trim()
            .escape()
            .notEmpty().withMessage('Please provide a category name.')
            .isLength({ min: 3 }).withMessage('Category name must be at least 3 characters long.')
            .isLength({ max: 100 }).withMessage('Category name cannot be longer than 100 characters.')
    ];
};

// 2. Applied in src/routes.js
router.post('/new-category', categoryRules(), registerCategory);

// 3. Handled in src/controllers/categories.js
import { validationResult } from 'express-validator';

const registerCategory = async (req, res, next) => {
    const { category_name } = req.body;
    
    // Extracts validation errors gathered by the middleware from the request object
    const errors = validationResult(req);

    // Evaluates if any validation rules were violated
    if (!errors.isEmpty()) {
        return res.render('categories/add-category', {
            title: 'Add New Category',
            errors: errors.array(), // Converts errors to an array to be looped over in EJS
            category_name
        });
    }
    
    // Proceed to database insertion if validation passes...
};

[Coach]: This is an excellent implementation of express-validator across your layers, Sampson. In your rules, you chain .trim() and .escape() right before checking if the field is empty or matching its length. Why is it critical to sanitize the input with methods like .trim() and .escape() before running validations like .notEmpty() or checking the length, rather than doing it afterward?

[Sampson]: It is critical to sanitize the input before running validations because sanitization directly alters the characters and length of the data being checked. Running these steps in the correct order prevents bypasses and ensures accuracy. If we validate first: The string "   " passes the .notEmpty() check because its length is 3. The application proceeds with invalid data. If we sanitize first: The .trim() method strips out all whitespace characters, reducing "   " to an empty string "". When .notEmpty() runs immediately after, it catches the empty string and correctly flags the validation error. The .escape() method converts dangerous HTML special characters into secure HTML entities to prevent Cross-Site Scripting (XSS) attacks. This process significantly expands the character count of the string.

[Coach]: Spot on, Sampson! Your explanation of how .trim() reduces whitespace to an empty string to catch bypasses is exactly why order matters. We have successfully covered all four required topics. You did a fantastic job explaining your design choices and technical logic today.
